Kalshi–Polymarket Arbitrage Server

Kalshi and Polymarket US often list the same real-world question, like which party wins the House, at slightly different prices. This server watches both exchanges around the clock, works out which contracts truly settle on the same outcome, and flags price gaps that would still be profitable after fees and order-book depth. It is read-only by design: it records, analyzes, and paper-trades, and never places a real order.

1 · Ingest REST catalog WebSocket books FIX market data
2 · Match Up to 3,000 markets Settlement-rule review
3 · Validate Fees & depth Data freshness Contract terms
4 · Output SQLite snapshots Paper trades · 8 strategies

Live, always-on pipeline

Ingests order-book data from both exchanges through REST, WebSocket, and FIX feeds, runs as a hardened Linux service, and logs snapshots to SQLite so any moment can be replayed.

Validation before any signal

An opportunity only counts if contract rules match, the data is fresh, and the book is deep enough after conservative fee math. A paper simulator tests 8 strategies without risking money.

Built with AI as a force multiplier. I used Claude and ChatGPT to plan the architecture, write and debug code, and scale a solo idea into about 7,300 lines of Python backed by 222 unit tests. Every piece of AI-generated code was reviewed and tested before it ran on the server.
